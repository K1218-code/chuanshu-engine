# 首页设计提示词：像素穿书终端

## 主提示词

优化“穿书引擎”的现有移动端书架首页，不改变原来的窗口顺序、DOM 标识、登录逻辑、故事加载、结局图鉴和新手指南。不要重做成传统营销落地页，而是把当前单列应用窗口升级成“二次元像素穿书终端”。

设计方向：90 年代掌机 RPG 菜单、像素视觉小说启动器、明亮日系配色与现代 AI 产品的清晰操作层级。桌面端让 720–820px 的原有应用成为漂浮在像素网格背景上的主窗口；移动端保持全屏原生应用体验。使用奶油纸色窗口、近黑色 2–3px 描边、硬边直角、4–10px 阶梯阴影。限定樱花粉、电光蓝、薄荷青、任务黄四色作为强调色。避免玻璃拟态、大圆角、通用紫色渐变 SaaS 和过量装饰。

必须基于现有窗口逐项优化：

1. 顶栏变成深色系统标题栏，保留演示登录与知乎登录；加入三个像素状态点和 `LIBRARY.EXE` 标识。
2. Hero 仍位于书架上方，改为穿书系统启动区：在线状态、像素狐图章、品牌主标题、产品说明、新手指南和动态世界数量。
3. “玩过的书、精选书库、更多入口、结局图鉴”仍保持原顺序，每个区块变成带编号和状态灯的独立窗口。
4. 故事卡继续使用现有横向信息布局，封面按顺序使用不同世界色；主按钮改成黄色像素任务按钮，保持“进入游戏”原功能。
5. 新手指南和结局图鉴浮层改成像素对话框，但内容与关闭逻辑不变。
6. 桌面端出现背景网格与少量漂浮像素；手机端隐藏这些纯装饰，保证内容宽度、触控尺寸和阅读效率。

交互要求：按钮按下移动 1–2px，卡片 hover 轻微抬升；状态灯使用低频 steps 动画；支持 `prefers-reduced-motion`。不得更改 `/game.html?book=...`、`create.html`、`stories.html`、OAuth 和 localStorage 数据协议。

## 验收标准

- 原有 4 个故事、2 个入口、登录、新手指南、玩过的书、结局图鉴全部可用。
- 1440px 桌面与 390px 手机均无横向溢出。
- 首屏能看懂“进入故事并改写命运”，而不是只看到装饰。
- 首页样式不泄漏到游戏、聊天、创建世界等其他页面。
